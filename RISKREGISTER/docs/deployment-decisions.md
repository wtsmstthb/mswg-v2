# MSWG RR Deployment Decisions

## Decided defaults

| Item | Decision |
|---|---|
| AWS region | `ap-southeast-1` (Malaysia) |
| Proposed production address | `risk.mswg.org.my` |
| Environment names | `dev` and `prod` |
| Resource-name prefix | `mswg-rr-<environment>` |
| Log retention | 30 days in `dev`; 90 days in `prod` |
| Risk/history retention | Indefinite unless MSWG approves a formal retention schedule |
| Risk deletion | No hard deletion through the application |
| Point-in-time recovery | Enabled in production DynamoDB tables |
| Deletion protection | Enabled in production DynamoDB tables |
| Backups | DynamoDB PITR in production; add scheduled AWS Backup only if the approved recovery policy requires retention beyond PITR |
| Archived-risk restore | Not available in the first release |
| Business owner | Proposed: Dr Ismet Yusoff; confirmation required |
| Technical owner | Interim: project developer; permanent MSWG/vendor successor required before production handover |
| Budget-alert recipients | Finance & Admin mailbox, Dr Ismet Yusoff, and the technical owner; exact company email addresses required |
| Account administrator | Proposed: Lini Hazlinda, with Dr Ismet Yusoff as approval/backup contact; confirmation required |

## Information still required before deployment

- Exact company addresses for the decided budget recipients: Finance & Admin mailbox, Dr Ismet Yusoff, and the technical owner.
- Confirmation of Lini Hazlinda as account administrator and Dr Ismet Yusoff as approval/backup contact.
- Confirmation of business and technical owners.
- Confirmation that 30/90-day CloudWatch log retention is acceptable.
- Recovery objectives: acceptable data-loss window (RPO) and service-restoration time (RTO).
- Whether the existing DNS provider will create the CloudFront alias record or delegate `risk.mswg.org.my`.
- Whether MSWG requires a formal multi-year backup archive in addition to DynamoDB PITR.

## Environment separation

- `dev` uses separate Cognito, DynamoDB, Lambda, API Gateway, S3, CloudFront, logs, and alarms from `prod`.
- Production identifiers and URLs are generated by infrastructure deployment and supplied to the frontend through environment-specific `config.js`.
- Local development uses DynamoDB Local through `DDB_ENDPOINT=http://localhost:8000`; AWS environments omit `DDB_ENDPOINT` and use IAM roles.
- No credentials, passwords, user-pool IDs, API URLs, table names, or local endpoints are embedded in application source.
